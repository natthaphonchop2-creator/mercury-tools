# Mercury v0.2.2 Strict Release Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish an immutable public Mercury `v0.2.2` release from the exact reviewed commit through a new upgradeable trusted release-control repository, deterministic history-free staging, provider attestation, secretless artifact build, and final public-install verification.

**Architecture:** `mercury-release-control-v2` is the only privileged control plane and treats Mercury source as untrusted bytes. Both repositories independently implement `PublicTreeV1`, compare the same reviewed Git archive, and bind staging, provider evidence, artifact handoff, and final publication to exact repository IDs, commits, workflow runs, and SHA-256 digests. Mercury retains product code and secretless builds; release-control creates staging, inspects Render/Supabase/FlowAccount, and publishes the final tag and draft-verified GitHub Release.

**Tech Stack:** Python 3.11-3.13, Pydantic 2, pytest 9, Ruff, Git/GitHub CLI, GitHub Actions, Render CLI/API, PostgreSQL/Supabase, gitleaks 8.24.3, trufflehog 3.88.32, uv 0.11.9.

## Global Constraints

- Target product repository: `natthaphonchop2-creator/mercury-tools`.
- Target control repository: `natthaphonchop2-creator/mercury-release-control-v2`.
- Existing `natthaphonchop2-creator/mercury-release-control` and tag `v0.2.1` remain unchanged audit evidence.
- Release version and final annotated tag are exactly `0.2.2` and `v0.2.2`.
- The target release-control commit must be merged and recorded before Mercury receives its exact 40-character pin.
- No Render, Supabase, FlowAccount, publication, or cross-repository write credential may exist in Mercury workflows, repository secrets, artifacts, logs, RAG, MCP output, or Git history.
- Privileged jobs may parse Mercury or pull-request files only as bounded data and may not import, source, or execute candidate code.
- `PublicTreeV1` consumes `git archive <reviewed-sha>`, rejects unsafe archive members, normalizes regular-file modes to `0755` or `0644`, and uses the exact digest record `<octal-mode> <path><NUL><sha256-of-file-bytes>` in sorted path order.
- Staging uses the immutable tag `v0.2.2-rc.<first-12-reviewed-sha>` and contains one unrelated commit only.
- Production ERP mutation is never part of release automation.
- Previously exposed credentials must be rotated before they enter the `production-release` environment.
- Manual secrets are entered through GitHub's environment UI or stdin-safe local commands and are never pasted into chat or command arguments.

```python
@dataclass(frozen=True, slots=True)
class PublicTreeEntry:
    path: str
    mode: int
    sha256: str
    content: bytes = field(repr=False)


def build_public_tree(archive_bytes: bytes) -> PublicTreeSnapshot:
    members = _read_bounded_tar(archive_bytes)
    entries = tuple(sorted((_entry(member) for member in members if _included(member.name)), key=lambda item: item.path))
    records = (f"{item.mode:o} {item.path}\0{item.sha256}".encode("utf-8") for item in entries)
    return PublicTreeSnapshot(entries=entries, digest=hashlib.sha256(b"".join(records)).hexdigest())
```

```python
class PublicationState(StrEnum):
    PRECONDITIONS_VERIFIED = "preconditions_verified"
    TAG_CREATED = "tag_created"
    DRAFT_VERIFIED = "draft_verified"
    PUBLISHED_IMMUTABLE = "published_immutable"


def require_transition(current: PublicationState, target: PublicationState) -> None:
    allowed = {
        PublicationState.PRECONDITIONS_VERIFIED: PublicationState.TAG_CREATED,
        PublicationState.TAG_CREATED: PublicationState.DRAFT_VERIFIED,
        PublicationState.DRAFT_VERIFIED: PublicationState.PUBLISHED_IMMUTABLE,
    }
    if allowed.get(current) is not target:
        raise PublicationError("publication_transition_invalid")
```
